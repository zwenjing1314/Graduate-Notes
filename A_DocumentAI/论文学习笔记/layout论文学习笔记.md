# Snappy

Snappy最核心的想法是：预训练模型已经能计算“问题与页面各个patch有多相关”，OCR已经能给出“页面上有哪些区域、分别在哪里”，再用固定的空间对应规则，就能把patch相关性变成候选框分数。

因此，它不需要另外训练一个区域排序器。不过，“不训练”指的是**不为这个定位任务额外训练**，它依赖的视觉检索模型和OCR模型本身都已经训练过。

**它到底解决什么问题？**

假设你问：“这篇文档中，营业收入增长的依据在哪里？”

普通页面检索可以返回相关页面，但页面里可能同时有标题、正文、表格和图片。Snappy继续回答：

> 这一页中，哪些已经解析出来的区域，更可能包含问题需要的证据？

它把两类信息结合起来：

| 信息来源              | 提供什么                             |
| --------------------- | ------------------------------------ |
| ColPali类视觉检索模型 | 问题与页面各位置的相关性             |
| OCR／布局解析器       | 段落、表格、图片等候选区域及其坐标   |
| 固定空间汇总规则      | 将相关性传递到候选区域，得到排序分数 |

**它的候选框排序，可以拆成四步。**

**第一步，分别编码问题和整页图像。**

问题编码为多个token向量：

$ Q=[q_1,\ldots,q_T]$​

页面编码为多个视觉patch向量：

$ P=[p_1,\ldots,p_N] $

以我们使用的ColPali接口为例，页面对应 \(32\times32=1024\) 个图像patch，每个向量128维。每个patch都有确定的页面位置。

不需要把每个候选框分别裁剪、送进视觉模型；整页编码可以被各候选共同使用。换用其他骨干时，则必须核实它实际的网格、缩放和token排列，不能机械套用ColPali的尺寸。

**第二步，计算问题token与patch的相似度。**

对每个问题token和每个patch计算余弦相似度：

$ S_{ti}=\operatorname{cos}(q_t,p_i)$​

这会得到一个 $T\times N$​ 的相似度矩阵。

同一个矩阵，可以有两种不同的读法：

| 目的               | 如何汇总                           | 输出              |
| ------------------ | ---------------------------------- | ----------------- |
| 页面检索           | 每个问题token找最相似patch，再求和 | 一个页面分数      |
| Snappy的空间相关性 | 每个patch找最相似问题token         | 每个patch一个分数 |

页面MaxSim是：

$ u_{\mathrm{page}}(Q,P)=\sum_t\max_i S_{ti}$

Snappy的patch相关分数是：

$ s_i(Q,P)=\max_t S_{ti}$

**关键变化是最大化方向不同。** 后者保留了1024个位置上的分数，因此可以画成页面热图。

论文经常称它为“attention”或解释图，但这里直接计算的是**嵌入相似度热图**，不应简单等同于Transformer内部的注意力权重。

**第三步，把候选框和patch放在同一个坐标系里。**

候选框可能使用原图坐标，而patch位于模型缩放后的图像网格。

例如，在ColPali的 $448\times448$ 输入中，每个patch是 $14\times14$ 像素。原始页面宽高为 $W,H$ 时，候选框坐标可以按以下比例缩放：

$x'=x\frac{448}{W},\qquad y'=y\frac{448}{H}$​

这样就能知道：一个表格候选框覆盖了哪些patch，边缘又与哪些patch部分相交。

这里做的是确定性的几何计算，不需要学习参数。

**第四步，将patch分数汇总成候选框分数。**

论文式（6）和式（10）的核心方案，是归一化IoU加权平均

$ r_j= \frac{\sum_i a_{ji}s_i}     {\sum_i a_{ji}}, \qquad a_{ji}=\operatorname{IoU}(R_j,B_i)$

其中：

- $R_j$：第 $j$ 个候选框；
- $B_i$：第 $i$ 个patch的空间框；
- $s_i$：该patch与问题的相关分数；
- $r_j$​：候选框最终分数。

直观上，就是看这个候选区域覆盖的patch整体上有多相关。除以权重总和，可以避免仅仅因为框覆盖更多patch，就不断累加出更大的分数；但这并不保证实际评分完全没有面积偏好。

最后按 $r_j$​从高到低排序即可。

另外，这里有两种IoU，必须分清：

- **评分时：候选框与patch框的IoU**，用作空间权重。
- **评测时：预测候选框与gold证据框的IoU**，判断是否定位成功。

**论文还做了什么，结论是什么？**

Snappy的完整系统包含两阶段：

1. 先用页面表示检索候选页面。
2. 再计算patch相关性，对页面内区域排序。

但论文的主要定位实验**直接给定正确页面，只评估第二阶段**。因此，我们沿用正确页面条件有明确的文献基础，并不是我们首次提出这个任务条件。

其主要实验使用BBox-DocVQA，1623个样本中排除4个OCR失败样本，实际评测1619个。结果包括：

| 骨干           | IoU≥0.5命中率 | 平均IoU |
| -------------- | ------------- | ------- |
| ColModernVBERT | 45.5%         | 0.480   |
| ColQwen3-4B    | 59.7%         | 0.569   |
| ColQwen3-8B    | 59.8%         | 0.569   |

**它和我们的论文，关系非常直接。**

我们继承了Snappy的两个基础：

- 正确页面条件下的页内证据定位设定。
- “问题与patch相关性 → 空间传播 → 候选区域分数”的读出链路。

我们的研究继续问：

> 冻结模型直接产生的patch表示，是否适合这项区域排序任务？如果先利用布局条件调整patch表示，再沿用固定评分，能否改善结果？

| 方法                | 核心链路                                                    |
| ------------------- | ----------------------------------------------------------- |
| B：冻结传播         | 原始 \(P\) → patch分数 → 固定区域汇总                       |
| C：普通适配         | 原始 \(P\) → 普通适配得到 \(P'_C\) → 同一固定评分           |
| D：布局条件适配     | 原始 \(P\)＋布局节点 → 局部融合得到 \(P'_D\) → 同一固定评分 |
| E：直接排序补充对照 | 原始 \(P\)＋问题＋候选布局 → 学习候选分数                   |

**C和D分别从原始 \(P\) 出发，是平行对照。** E则在主实验结束后加入，用来检验是否有必要先改写patch表示。

因此，我们不是重新提出Snappy的传播公式。我们的主要比较发生在：**保留冻结表示接口和共同候选时，适配表示与直接排序分别能带来什么收益。**

已有结果支持D-no-text相对B和C-wide的首位收益，但没有可靠超过面积，也没有建立相对E的额外优势。这个结论限定了适配方案的效果，并不否定Snappy提供的基础链路。

**至于“我们如何复现”，目前实际上已经完成了一部分。**

我核对了我们的评分函数：`patch_scores`计算问题token最大相似度，`patch_iou_matrix`建立候选—patch的IoU矩阵，`region_scores`执行归一化加权平均；代码还明确注明没有分位数筛选。  

本地Snappy官方实现中的区域评分函数，也包含同样的token最大聚合、IoU归一化加权平均，以及max、mean备选方式。  

因此，当前B可以准确称为：

> **采用Snappy核心传播评分的冻结参照。**
