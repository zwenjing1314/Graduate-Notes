# Cursor 的rules三种互不叠加的触发方式

 Cursor 有三种互不叠加的触发方式，一个规则用哪一种，看的是 frontmatter 里字段怎么组合：

| 触发方式                    | frontmatter 写法                                      | 触发逻辑                                               | 是否用「描述匹配」判断         |
| :-------------------------- | :---------------------------------------------------- | :----------------------------------------------------- | :----------------------------- |
| Always（常驻）              | `alwaysApply: true`                                   | 无条件注入，不看描述                                   | 否，描述基本不参与判断         |
| Agent Decides（智能判断）   | `alwaysApply: false` 且不写 globs，只写 `description` | 模型读 description，判断与当前任务是否相关，相关才加载 | 是，这就是你说的那条路径       |
| Auto Attached（按文件匹配） | `alwaysApply: false` 且写 `globs`/`paths`             | 当前打开/编辑的文件匹配 glob 就自动附加                | 否，纯机械匹配，不经过模型判断 |

所以正确的画面是：

```
"alwaysApply: true"        = 不看描述，永远注入
"仅 description，无 globs"  = 模型判断描述是否相符，相符才注入   ← 你描述的其实是这一条
"globs/paths"              = 文件路径匹配，匹配就注入
```

我看了github的issues有类似的问题，解决方法为：
原因 是因为该脚本文件的换行符格式错误。 该脚本目前使用的是 Linux/macOS 风格的换行符（LF / \n），而 Windows 的批处理文件（.bat）必须使用 Windows 风格的换行符（CRLF / \r\n）。当 Windows 命令提示符（cmd.exe）执行带有 LF 换行符的批处理文件时，会发生读取错位，把代码截断成乱码指令去执行，从而导致报错并瞬间闪退。
将 启动汉化_Win.bat 的换行符从 LF 转换为了标准的 CRLF即可。
